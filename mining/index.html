Mining

What you need, how to start, and what the miner gives away. Nothing you mine on gamma has any value, and the network can be reset. Mining runs your GPU at full load: you pay for the electricity.

What you need

To mine withYou needKnown to work?
An NVIDIA GPU RTX 30 series or newer (compute capability 8.0+), a driver for CUDA 13 (R580 or newer). The CUDA Toolkit is not needed. The 4 GiB dataset lives in video memory. Yes, on the author's RTX 5070 Ti (16 GB). Whether an 8 GB card works is untested.
An AMD GPU Linux only: an RX 7000 (RDNA3) or RX 9000 (RDNA4) card, AMD's ROCm 7, and the Linux AMD package (…-linux-x64-amd). About 5 GiB of video memory. Not run by anyone on the project in this version. Contributed by qcvibes1, who checked it bit for bit on their own RX 7000 card, before the move to ROCm 7. Card by card.
A CPU Nothing extra, but about 9 GiB of RAM with a node (the miner builds its own dataset). Works, but impractical on gamma: far too slow next to a GPU.

For a sense of scale, measured on one RTX 5070 Ti: about 43,000 to 45,000 attempts a second, limited by the card's memory bandwidth. Nothing is claimed about any other card. The difficulty follows the miners, so how often you find a block depends on everyone else (the home page shows the current difficulty and an estimated network hash rate).

Alone, or in the pool

Alone, on your own node

Every block you find pays you the whole reward (20 coins now), and nobody stands between you and it. You need a node (about 4.3 GiB of RAM, besides the miner). With little hash rate you may wait a long time for a block.

In the test pool

Many miners share the rewards (PPLNS), so payouts come steadily but smaller. No node is needed to mine, but you need one to see and spend what the pool pays. A pool keeps the block rewards and pays by its own rules; nothing makes it pay. It also sees your address and your IP address. The pool's numbers.

Mining with the wallet app

  1. Download the release for your system from the Releases page and check it. For an AMD card, use the Linux AMD package.
  2. Start tenero-wallet-gui, create a wallet, and write down the 24 words. They are the wallet.
  3. For mining alone, start the node on the Node tab and wait until it is in sync. For the pool, you can skip this.
  4. On the Mining tab choose "On a pool" or "Alone, on my own node", then press Start. For AMD: Settings, Mining, Backend, amd.

The tab shows the rate over 10 s, 60 s, 15 min and the whole run, the card's temperature, power and clocks, and the blocks (or shares) found. Nothing mines until you press Start, and it stops when you lock the wallet or stop the node.

Mining from the command line

For the test pool, with no node (Windows; on Linux, ./tenero-miner):

.\tenero-miner.exe --pool default --network gamma --address TENg... --backend gpu

Alone, on a node running on the same computer:

.\tenero-miner.exe --data YOUR-NODE-FOLDER --address TENg... --backend gpu
  • --address is your wallet's main address (it starts TENg), not a subaddress.
  • --backend is gpu (NVIDIA), amd (the Linux AMD package only) or cpu.
  • --pool default is the test pool, its key built in and pinned: a machine pretending to be the pool is refused.
  • For the pool through Tor, add --proxy 127.0.0.1:9050 (a Tor program must be running).
  • Everything else: tenero-miner help, and RUNNING.md.

The miner's fee: 1% of the mining time

Since 0.4.0 the project's miner works one minute in every hundred for the author of the backend you use, instead of for you. It was agreed with the community before it shipped.

  • How: alone, the block template of a fee minute pays the fee's address; in a pool, the miner logs in with the fee's address for that minute. The first fee minute falls at a random point in the first 100 minutes. It is fair on average, not block by block.
  • Always shown: the miner's banner, its log and the screen say when a fee minute starts and ends, and a block found in one is shown as the fee's, not counted as yours. The app shows it on the Mining tab and in Settings.
  • Fixed: there is no setting to turn it off. The code is open (fee.rs, the addresses), and anyone may build a miner without it.
  • The test pool charges no fee of its own. The fee is the miner's, not the pool's, and consensus is not touched: a fee block is an ordinary block.

If something goes wrong

  • Antivirus: it may call the miner a "coin miner". It is one. Check the download's hash, and if you decide to trust it, exclude only its own folder.
  • A block "refused": the node checks every block completely. A refused block is wasted work, never a bad block in the chain. With AMD, report it: it may mean that card computes something wrongly.
  • "Lost a race": someone else's block for the same height arrived first. It happens; it is not a fault.
  • A stop notice is only ever posted in issue #1. Questions and bug reports: the Discord server.
